## Что такое транзакция?

**Транзакция** — это одна логическая операция работы с базой данных, которая может состоять из одной или нескольких SQL-команд.

Главное свойство транзакции:

> либо выполняются все команды внутри транзакции, либо при ошибке не применяется ни одна из них.
## Зачем нужны транзакции?

Транзакции нужны для того, чтобы база данных не переходила в некорректное промежуточное состояние. Т.е. чтобы не возникало ситуации, когда данные не должны были обновиться.

Рассмотрим простой пример с переводом денег.

Есть таблица `Money`:

|id|name|money_count|
|--:|---|--:|
|1|Niko|1500|
|2|Kane|1200|

Нужно перевести `300` денежных единиц от `Niko` к `Kane`.

Логически перевод состоит из двух действий:

1. Списать `300` у `Niko`.
2. Добавить `300` к `Kane`.

На SQL это можно записать так:

```sql
UPDATE Money
SET money_count = money_count - 300
WHERE id = 1;

UPDATE Money
SET money_count = money_count + 300
WHERE id = 2;
```

Проблема в том, что эти две команды обязательно должны выполниться вместе, чтобы считать перевод денег завершенным.

Если первая команда выполнится, а вторая нет, получится неправильное состояние базы данных.

Например, если после первой команды произойдет ошибка, то данные станут такими:

|id|name|money_count|
|--:|---|--:|
|1|Niko|1200|
|2|Kane|1200|

Деньги у `Niko` списались, но `Kane` их не получил.

То есть `300` денежных единиц просто исчезли в никуда, что ни в коем случае нельзя допускать.

## Как транзакция решает эту проблему?

Если обернуть эти две команды в транзакцию, база данных будет воспринимать их как одну цельную операцию. Точнее база данных будет делать много операция и действий внутри себя, но для клиента эта операция будет восприниматься как одна.

Если обе команды выполнятся успешно, то необходимо послать команду `COMMIT`, то есть зафиксируем изменения.

Если произойдет ошибка, то необходимо послать команду `ROLLBACK`, то есть откатить все к чертям обратно.

Общий синтаксис транзакции выглядит так:

```sql
BEGIN;

-- SQL-команда 1
-- SQL-команда 2
-- SQL-команда 3

COMMIT;
```

Если внутри транзакции произошла ошибка:

```sql
BEGIN;

-- SQL-команда 1
-- SQL-команда 2

ROLLBACK;
```

То есть мы отправляем команду `BEGIN;`, после этого выполняем нужное количество SQL-команд, а дальше в зависимости от результата отправляем финальную команду: `COMMIT;`, если все операции внутри транзакции выполнились успешно, или `ROLLBACK;`, если во время выполнения произошла ошибка и нужно отменить все изменения, сделанные с момента `BEGIN;`. 

Обычно в языках программирования драйверы, ORM или фреймворки могут автоматически управлять транзакциями: например, оборачивать отдельную SQL-команду в транзакцию или предоставлять специальный контекст, внутри которого разработчик выполняет несколько команд, а затем явно или автоматически вызывается `COMMIT` либо `ROLLBACK`. Даже базы данных просто каждую команду автоматически оборачивают в транзакцию под капотом.

Даже отдельную SQL-команду нужно выполнять внутри транзакции, потому что “под капотом” одна команда в базе данных превращается во множество внутренних действий. Например, при выполнении `INSERT` база должна:
1. Найти место для новой строки в таблице.  
2. Записать новую строку в страницу данных.  
3. Обновить индекс, если установлен.  
4. Записать информацию в WAL журнал.  
5. Изменить служебные метаданные.  
6. Сделать изменения видимыми другим транзакциям.

### Правильный пример с переводом денег

Перевод `300` денежных единиц от `Niko` к `Kane` нужно записать так:

```sql
BEGIN;

UPDATE Money
SET money_count = money_count - 300
WHERE id = 1;

UPDATE Money
SET money_count = money_count + 300
WHERE id = 2;

COMMIT;
```

Теперь база данных гарантирует, что перевод будет выполнен целиком.

Если обе команды успешно выполнятся, итоговая таблица будет такой и общая сумма денег не изменится:

|id|name|money_count|
|--:|---|--:|
|1|Niko|1200|
|2|Kane|1500|

## Главная идея

Транзакция нужна для того, чтобы несколько связанных SQL-команд выполнялись как одно целое действие.

Если действие завершилось успешно — изменения фиксируются через `COMMIT`.

Если действие завершилось с ошибкой — изменения отменяются через `ROLLBACK`.

Коротко:

```text
BEGIN    — начать транзакцию
COMMIT   — подтвердить изменения
ROLLBACK — отменить изменения
```

Самая важная мысль:

> Транзакция защищает базу данных от частично выполненных операций.
